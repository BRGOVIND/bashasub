BhashaSub Subtitle quality control

Subtitle quality control, without the guesswork.

Reading speed is one of the most common reasons subtitle files get rejected. BhashaSub reads a subtitle file properly — cue by cue, in the script it is actually written in — and explains what would fail before anyone else sees it.

The conformance checker is still being built. What runs here today is the translation tool below; the parsing and measurement core it will sit on is already in the repository.

What the core does today

These are implemented and covered by tests, not planned.

  • Reads real files

    Detects UTF-8, byte-order marks, UTF-16 and legacy codepages, and says so when a file is ambiguous rather than quietly mangling it.

  • Parses cue by cue

    An SRT file becomes timed cues with source line numbers, so a problem can be pointed at the exact line that caused it.

  • Keeps time honestly

    Timing is whole milliseconds, and frame-based rules convert against a real frame rate — two frames is 80 ms at 25 fps but 84 ms at 23.976.
